# DS-007 Decision Governor Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** while a chat is streaming tokens, the gateway sends decision work to vLLM in short
waves, one call at a time, with decode-only gaps between calls. Chat keeps decoding fast,
and decisions run at full speed when no chat is streaming.

**Architecture:** a new `gateway/governor.py` counts chat streams that are decoding and
gates `Readout._call`:
- **No chat decoding:** calls pass straight through.
- **Chat decoding:**
  - decision rows go in waves of `GOVERNOR_WAVE` rows;
  - one decision call is in flight at a time;
  - after each call the governor pauses `elapsed × (1 − duty) / duty`, so decisions hold
    about `duty` of GPU time;
  - the pause ends early if the last chat finishes.

`duty = 1.0` turns the governor off, with behaviour and request bodies identical to today.

**Tech Stack:** Python 3.12, asyncio, FastAPI/Starlette `StreamingResponse`, httpx, pytest
(asyncio auto mode, `httpx.MockTransport`).

**Spec:** DS-007 (ticket; owner direction "chat gets higher priority than systemone", task
G1); `docs/appendix/ds007-scheduling.md` §3a; sweep evidence
`docs/results/archive/ds-025-007-sweep.md` (vLLM settings alone reach 3.0 chunks/s on Qwen,
0.5–0.7 on gemma).

## Global Constraints

- Pass bar (DS-007):
  - chat TTFT p50 ≤ 0.5 s;
  - ≥ 10 chunks/s under 4 systemone workers;
  - systemone ≥ 0.32 req/s;
  - 0 preemptions.
- `GOVERNOR_DUTY` default `1.0` (off) in code; `GOVERNOR_WAVE` default `4`. Valid: `0 < duty ≤ 1`, `wave ≥ 1`; anything else fails at startup with a `ValueError` naming the variable.
- Only **streaming** chat counts as decoding. It counts from its first upstream chunk until the stream ends, errors, or the client leaves. Non-streaming chat and `/v1/*` passthrough never count.
- Decision answers must be identical with the governor on or off (same rows, same label ids, same order); only timing changes.
- Code reads like a tutorial; comments ≤ 2 lines; no new dependencies.
- Commits: caveman Conventional Commits, subject ≤ 50 chars, explicit `git add` paths, trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. A chat stream that ends abnormally (client disconnect, upstream error mid-stream) must still decrement the count. A leaked count would throttle decisions forever. → Task 3 test `test_stream_count_drops_when_client_leaves_mid_stream`.
2. A decision cancelled while it holds the slot or sleeps in its pause (client left) must free the slot for the next decision. → Task 1 test `test_cancelled_call_frees_the_slot`.
3. When the last chat finishes, a decision waiting in a pause must resume right away, not after the full pause. → Task 1 test `test_pause_ends_when_last_chat_ends`.
4. Waves combined with label-id chunking (>128 ids) must still return each row's logprobs for its own labels, in order. → Task 2 test `test_waves_and_label_chunks_keep_row_order`.
5. With `duty = 1.0`, request bodies and call counts are exactly today's. → Task 2 test `test_duty_one_sends_exactly_todays_calls`.

### Task 1: Governor module and settings

**Files:**
- Create: `gateway/governor.py`
- Modify: `gateway/config.py` (Settings fields + `from_env`)
- Test: `tests/unit/test_governor.py`, `tests/unit/test_config.py`

**Interfaces:**
- Produces:
  - `class Governor` with:
    - `__init__(self, duty: float = 1.0, wave: int = 4)`; raises `ValueError` outside `0 < duty ≤ 1` or `wave < 1`;
    - `enabled: bool`, i.e. `duty < 1.0`;
    - `decoding: int`, the count of chat streams decoding;
    - `chat_started() -> None`, `chat_ended() -> None`; `chat_ended` never goes below 0;
    - `throttling() -> bool`, i.e. `enabled and decoding > 0`;
    - `wave_size() -> int | None`: `wave` when throttling, else `None`;
    - `async call(fn: Callable[[], Awaitable[T]]) -> T`.
  - `Settings.governor_duty: float = 1.0` (env `GOVERNOR_DUTY`) and `Settings.governor_wave: int = 4` (env `GOVERNOR_WAVE`); empty or missing env gives the default.

- [ ] **Step 1: Write failing tests** in `tests/unit/test_governor.py`. Use a fake clock or real `asyncio` with tiny durations (≤ 50 ms) and `pytest` asyncio auto mode as other tests do.
  - `test_off_by_default_passes_calls_through`: `Governor()` gives `enabled is False`; after `chat_started()`, `throttling()` is False and `wave_size()` is None; `await g.call(f)` returns f's value with no pause.
  - `test_invalid_settings_raise`: `Governor(duty=0)`, `Governor(duty=1.5)` and `Governor(wave=0)` each raise `ValueError`.
  - `test_counts_streams_and_never_goes_negative`: two starts and three ends leave `decoding == 0`.
  - `test_one_call_in_flight_while_throttling`: with duty 0.5 and one chat started, two concurrent `call`s whose fns record enter/exit times don't overlap.
  - `test_pause_follows_duty`: with duty 0.25 and chat decoding, a call whose fn takes ~20 ms delays the next call's start by ≥ 55 ms (3 × 20 ms, with tolerance).
  - `test_pause_ends_when_last_chat_ends`: with duty 0.1 and fn ~30 ms (pause ~270 ms), calling `chat_ended()` 20 ms into the pause lets the next call start within 50 ms.
  - `test_no_pause_when_no_chat`: with duty 0.25 and no chat, two concurrent calls overlap.
  - `test_cancelled_call_frees_the_slot`: cancel a task blocked in `call` (in its fn, then in its pause), then a new call completes within 100 ms.
  - In `tests/unit/test_config.py`, `test_governor_env`: `GOVERNOR_DUTY=0.25` and `GOVERNOR_WAVE=2` parse; missing or empty values give `1.0` and `4`.
- [ ] **Step 2: Run** `uv run pytest tests/unit/test_governor.py tests/unit/test_config.py -q`. Expected: FAIL (`gateway.governor` missing).
- [ ] **Step 3: Implement `Governor`.**
  - An `asyncio.Lock` serialises calls only while throttling.
  - An `asyncio.Event` named `idle` is set when `decoding == 0`.
  - The pause is `await asyncio.wait_for(idle.wait(), timeout=pause)`, with the timeout swallowed. Measure elapsed time with `time.monotonic()`.
  - Decide whether to take the lock at call start; take the pause only if still throttling after the fn returns.
  - Add the two Settings fields following `systemone_priority`'s style.
- [ ] **Step 4: Run** the same tests. Expected: PASS. Then `uv run ruff check gateway tests`.
- [ ] **Step 5: Commit** `gateway/governor.py gateway/config.py tests/unit/test_governor.py tests/unit/test_config.py` with `feat(gateway): decision governor`.
