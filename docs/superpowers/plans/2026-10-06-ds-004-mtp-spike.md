# DS-004 spike plan: MTP speculative decoding alongside systemone

**Goal:** find out whether chat can run MTP while `/v1/systemone` stays exact, and measure
the cost. Output is one recommendation per profile with A/B numbers (ticket verify
criteria): max |dp|, argmax flips, systemone latency, chat tokens/s with and without MTP.

**Scope:** Qwen3.6-27B and Qwen3.8-27B. Gemma 4 31B was dropped on 2026-10-06 after step 0:
its low label logprobs and high T (4.3-7.6) make a top-K read move probabilities by up to
0.6-0.8.

**Rules agreed with the owner (2026-10-06):**

- Stop after each step and report before starting the next.
- GPU time is approved for this spike.
- No ship thresholds up front: measure both profiles, then decide per profile at the end.
- Spike code lives on branch `spike/ds-004-mtp` and is throwaway; only results and the
  write-up land on `main`.

## What vLLM 0.30 does (source read, not yet measured)

- **Label ids are lost with MTP on.** If any request in a step has draft tokens, the
  whole batch goes through the rejection sampler (`v1/worker/gpu/model_runner.py:1552-1564`),
  which calls `compute_topk_scores` without `logprob_token_ids_state`
  (`v1/worker/gpu/spec_decode/rejection_sampler.py:142-148`). A decision row then gets an
  empty logprobs list and the completions endpoint raises `IndexError`
  (`entrypoints/openai/completion/serving.py:673`). If a co-batched chat asked for top-k,
  the row gets that top-k instead of its labels. Intermittent: only when a decision
  shares a step with a drafting chat. No per-request switch exists.
- **Top-K is exact but incomplete.** `logprobs=K` uses the target logits through the same
  `compute_topk_scores` as the non-MTP path. `max_logprobs` defaults to 20; full vocab
  (`-1`) is impractical. Practical K is 20-64.
- **Collected data says top-K will miss labels** (`.cache/collect/*/eval.jsonl.gz`, header
  layout, 2,827 questions): 7.4% have more than 64 labels; questions with a label below
  logprob -12: Qwen3.6 13%, Qwen3.8 13%. Calibration T > 1 lifts these
  (p = 6e-6 becomes ~2e-3 at T ≈ 1.9), so how missing labels are filled matters.
- **Hybrid Qwen prefix cache.** With MTP the block becomes 800 tokens and the Mamba
  checkpoint steps back one block (`kv_cache_coordinator.py:155-159`): prompts under ~1,601
  tokens get no prefix hit.
  `disable_eagle_block_drop` (`config/speculative.py:440-444`) is said to change only
  acceptance.
- **MTP weights.** Both Qwen checkpoints carry one MTP module (15 `mtp.*` tensors); with
  `num_speculative_tokens` 3 it drafts recursively.
- **Token budget.** A drafting decode costs 1+K tokens of `--max-num-batched-tokens`;
  vLLM warns below 8192. The Qwen profiles run 2352 with a 784 threshold (DS-025), so
  drafts eat into that margin. The spike keeps the shipped values and measures the effect.
- Keep the KV cache bf16 (#49010: fp8/nvfp4 KV + MTP corruption on sm_120). Avoid
  `prompt_logprobs` (#53488).

## Step 0: offline top-K simulation (CPU only) (done)

From the collect records, keep each question's top-K labels, then apply calibration and
`orders.average_back`. Fill missing labels two ways: at the K-th logprob (upper bound)
and at -inf (lower bound). Report max |dp| and argmax flips versus the full read, for
K = 20, 32, 64, per profile. The bracket shows whether a top-K readout is worth a GPU run.

Result (`docs/results/ds-004/topk-sim.md`): 0 argmax flips in every cell. At K = 64,
max |dp| (upper / lower fill) is 0.12 / 0.03 for Qwen3.6 and 0.09 / 0.02 for Qwen3.8 at
θ = -12; score and noul questions do not move for θ ≤ -12. All error is on choice
questions with more than 20 labels. The cutoff θ matters far more than K.

## Step 1: spike harness

- `READOUT=topk` in `gateway/readout.py`: `logprobs=K` instead of `logprob_token_ids`;

- Profile variants: `--speculative-config {"method":"mtp","num_speculative_tokens":3}`
  and `--max-logprobs 64`, written without spaces because the entrypoint word-splits
  `EXTRA_ARGS`.

## Step 4: patched vLLM (approved 2026-10-06; upstreaming decided during this step)

Give the rejection sampler the same label-id path the normal sampler uses, so arms
A′/D/E can be rerun with exact label reads. v0.31.0 still has the gap
(`model_runner.py:1625`, "Rejection sampler does not return logprob token ids").

- `rejection_sampler.py`, `__call__`: replace `sampling_states.max_num_logprobs(...)` with
  `self.sampler.get_logprobs_dims(input_batch.idx_mapping_np)`, which returns
  `(num_logprobs, max_per_req_token_ids)`.
- `_get_logprobs_tensors`: pass `logprob_token_ids_state=self.sampler.logprob_token_ids_state`,
  `expanded_idx_mapping=input_batch.expanded_idx_mapping[lo:hi]` and
  `max_per_req_token_ids` to `compute_topk_scores`, as `sample/sampler.py:162-171` does.
- `model_runner.py`: `include_token_ids=True` in the TP gather (no effect on one GPU).
- Ship it as a bind-mounted file in a compose override, image digest unchanged.

## Open: prefix sharing under MTP

JevBench rows are single questions (0% cached tokens), so they cannot show prefix sharing.
With MTP the block is 800 tokens but the gateway still pads shared prefixes to 784
(`PREFIX_BLOCK=784`), so multi-question requests may lose their shared-prefix reuse.
Test with a multi-question bench under MTP, padding to 784 vs 800.
