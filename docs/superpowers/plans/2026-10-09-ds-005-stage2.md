# DS-005 Stage 2: Calibrate the Quantized Profiles

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** turn the four quantized arms the owner picked after the Stage 1 screen into real profiles, and fit and judge a calibration for each. Then report against bf16 and close DS-005 with a recommendation.

**Architecture:**
- Stage 1 left throwaway `ds005-*` profiles, labels and bench runs in the working tree.
- Task 1 commits the Stage 1 results the way DS-004 did, and Task 2 deletes the throwaway arms.
- Task 2 also promotes the four picks to committed profiles: Qwen3.8 FP8, Qwen3.8 NVFP4, Qwen3.6 FP8, and Gemma FP8 + fp8 KV.
- Tasks 3-6 run the existing collect → calibrate pipeline once per profile.
- Task 7 writes the final table.
- No gateway code changes. The only infra change is passing `VLLM_USE_DEEP_GEMM` through compose.

**Tech Stack:** vLLM 0.30.0 (patched rejection sampler), docker compose, `scripts/collect.py`, `scripts/calibrate.py`, `scripts/build_labels.py`, `scripts/compare_runs.py`, DoStuff (DS-005).

**Spec:** DS-005 verify criteria: a table per quantized profile vs bf16 with accuracy, ECE before and after refit, p50/p95 latency and free KV GB, plus a written recommendation. Stage 1 numbers are in `docs/results/ds-005/README.md` (Task 1).

## Global Constraints

- **Calibration data:** never calibrate, fit or tune on Jev API outputs. Fit only on `data/splits/calib.json`, and judge on eval.
- **Calibration validity:** a calibration is valid for one model + precision + layout + option-order setting. Each new profile is collected and fit from scratch, and no bf16 calibration file is ever copied into a quantized profile.
- **Quantized Qwen with MTP:** always pass `--kv-cache-dtype bfloat16`. Without it, RadixArk's `kv_cache_scheme` turns `auto` into fp8 KV, and fp8 KV with MTP corrupts output on sm_120 (vLLM #49010).
- **Every quantized profile:** `VLLM_USE_DEEP_GEMM=0`. DeepGEMM crashes or logs noise on sm_120 (#51884, #60261).
- **Label tables:** built with `scripts/build_labels.py` from each profile's own checkpoint, never copied. The Gemma FP8 template differs from base by one trailing newline, so its `tokenizer_sha256` differs.
- **GPU pauses:** stop after every collect step for a GPU break, and report before starting the next one (owner's rule).
- **Commits:** caveman Conventional Commits, subject ≤ 50 chars. Stage explicit paths only, never `git add -A`.
- **Comments:** at most two lines.

## Review Focus

- **Silent fp8 KV:** a quantized Qwen profile without `--kv-cache-dtype bfloat16` boots fine and silently runs fp8 KV under MTP. Pinned by `test_quantized_mtp_profiles_force_bf16_kv` (Task 2).
- **Empty DeepGEMM value:** an empty `VLLM_USE_DEEP_GEMM` reaches vLLM as `""`, and `int("")` crashes engine startup. Compose must default it to `1`. Pinned by `test_compose_passes_deep_gemm_with_default` (Task 2).
- **Stale stamps:** the new Qwen calibration files must be stamped `prefix_block 800`, or the gateway refuses them. Pinned by extending `test_shipped_qwen_calibration_is_stamped_for_the_profiles_block` (Tasks 3-5).
- **Old collect files:** a collect file for a new profile must start empty. `collect.py` refuses mixed stamps, so check that `.cache/collect/<profile>/` does not exist before each first collect.
- **Copied labels:** Gemma FP8 labels must be built from the FP8 repo, not copied from `gemma-4-31b`. Task 2, Step 4 checks that the ids match and that the hash comes from the FP8 checkpoint.
